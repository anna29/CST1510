Topic 2 — Methods

A dictionary can only hold data. An object can hold data and the actions that belong to it — a method is how an object is given those actions.

1.What is a method?

A method is a function with one structural difference: it is defined inside a class, and its first parameter is always self. That single difference changes how it is called. A plain function, of the kind introduced in Week 3, needs every piece of data passed to it explicitly, every time — summary_function(label, value, limit). A method already lives on the object, so it only needs to ask for information it does not already have. self is what gives it access to everything the object already holds.

It is worth seeing what Python is actually doing when an object is constructed. Writing

r = Record("R-001", 87.0, 100.0)

is shorthand for something close to Record.__init__(new_object, "R-001", 87.0, 100.0). Python builds the empty object first, then passes that very object in as self. This call is never written by hand — Python fills the first slot in automatically. That is the entire reason every method requires self as its first parameter, even though it is never supplied at the call site.

class Record:
    def __init__(self, label, value, limit):
        self.label = label
        self.value = value
        self.limit = limit

    def summary(self):
        """Return a one-line description of this record."""
        return f"{self.label}: {self.value}/{self.limit}"

r = Record("R-001", 87.0, 100.0)
print(r.summary())
OutputR-001: 87.0/100.0

2.Self is whichever object made the call

This is the point at which the idea usually resists a first reading: self is not a keyword and it is not fixed to any one object. The same method code, written once, resolves self differently depending on which object stood before the dot at the moment of the call. r_a.summary() and r_b.summary() run the identical line of code, yet inside each call self becomes r_a for one and r_b for the other.

r_a = Record("R-001", 87.0, 100.0)
r_b = Record("R-002", 120.0, 100.0)

print(r_a.summary())    # self was r_a here
print(r_b.summary())    # self was r_b here, same method
OutputR-001: 87.0/100.0
R-002: 120.0/100.0

3.One method can call another, through self

Because self is the object, a method may call another method on that same object simply by writing self.other_method() — no different from calling any function, except the object need not be passed in again, since it is already there. This is how small pieces of behaviour build into larger ones without repeating logic: status, below, does not recompute a percentage itself; it asks percent for it.

class Record2:
    def __init__(self, label, value, limit):
        self.label = label
        self.value = value
        self.limit = limit

    def percent(self):
        """Return value as a percentage of limit."""
        return (self.value / self.limit) * 100

    def status(self):
        """Return OVER LIMIT, WARNING or OK based on percent()."""
        p = self.percent()
        if p >= 100:
            return "OVER LIMIT"
        elif p >= 90:
            return "WARNING"
        else:
            return "OK"

r2 = Record2("R-002", 95.0, 100.0)
print(r2.status())
OutputWARNING

4.A method can change its own object's state

Week 3 established a firm rule: a function cannot reach outside itself and change a caller's variable — whatever it does to its parameters is discarded the moment it returns, unless the return value is explicitly captured. A method is a genuine exception to this rule, not a contradiction of it. self is not a copy of the object; it is the object. When a method writes self.some_attribute = new_value, the change is real, and persists to the next call made on that same object.

The wall from Week 3 is still standing — a method simply holds a key to its own room. It still cannot reach into another object's attributes; it can only change the one object it belongs to.

class Checker:
    def __init__(self):
        self.over_limit_count = 0

    def check(self, value, limit):
        """Update the running count if value is over limit."""
        if value > limit:
            self.over_limit_count += 1

c = Checker()
c.check(120, 100)
c.check(87, 100)
print(c.over_limit_count)   # 1 — it actually changed, no return needed
Output1
