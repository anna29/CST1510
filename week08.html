Week 8 — Pulling Real Data

By the end of this week you can call a real web API with requests, read its status code, and parse its JSON, handle a failed or slow request without your program crashing, and download a real file from the web — a raw GitHub URL or a Kaggle dataset.

Part 1

Calling a Web API

Official docs: Requests quickstart · json module

Everything you have loaded so far has been a file you already had. This week it is a real service, somewhere else, that you ask for data.

1.A GET request asks a URL for something

import requests

response = requests.get("https://api.github.com/orgs/python")
print(response.status_code)
your code                the API
    │                        │
    │──── GET request ──────▶│
    │                        │  looks it up
    │◀─── response ──────────│
    │   (status code + JSON)

2.Status codes tell you what happened

200s = OK. 400s = you got something wrong. 500s = their fault, not yours.

print(requests.get("https://api.github.com/orgs/python").status_code)              # 200
print(requests.get("https://api.github.com/this-does-not-exist-xyz").status_code)     # 404

3..json() turns the response into Python data

Almost every API replies in JSON — which looks exactly like a dict, or a list of dicts.

response = requests.get("https://api.github.com/orgs/python")
data = response.json()
print(data["login"], data["public_repos"])

4.Query parameters, and always set a timeout

The params dict becomes ?key=value on the URL for you. A timeout stops a dead server from hanging your program forever.

response = requests.get(
    "https://api.github.com/orgs/python/repos",
    params={"per_page": 3, "sort": "updated"},
    timeout=10,
)
for repo in response.json():
    print(repo["name"], repo["open_issues_count"])

5.Handling a missing field safely

Not every response has the field you expect — an API can change shape, or you can mistype a key. dict.get(key, default) returns a fallback instead of raising KeyError; wrapping the lookup in try/except KeyError works too.

data = requests.get("https://api.github.com/orgs/python").json()

# data["repo_count"] would raise KeyError - that field does not exist.
# .get() returns a fallback instead of crashing:
repo_count = data.get("repo_count", "unknown")
print(repo_count)

# safe to use the same way even on a field that does exist:
print(data.get("public_repos", "unknown"))

Same idea, three fields

Field Looks like
AI / Data Science pulling a public dataset's metadata from an API before downloading it
Cyber Security pulling a threat-feed or breach-notification API
IT pulling live status from a monitoring or ticketing API

Common mistakes

Mistake What you see Fix
indexing response directly, e.g. response["login"] TypeError: 'Response' object is not subscriptable call .json() first
a key that does not exist in the JSON KeyError print the whole dict first and check the real field names; use .get(key, default) if the field is genuinely optional
no timeout= the program can hang indefinitely on a dead server always set one
forgetting params= and hand-building the URL string works, but fragile and easy to get wrong let requests build the query string

Part 2

Reading Files from the Web

Official docs: Requests quickstart · pandas.read_csv

Not every dataset needs an API — sometimes it is a file sitting on the web, waiting to be downloaded.

1.A "raw" GitHub URL serves the real file

github.com/user/repo/blob/... shows a formatted web page. raw.githubusercontent.com/user/repo/branch/... gives you the actual file.

import requests

url = "https://raw.githubusercontent.com/mwaskom/seaborn-data/master/iris.csv"
response = requests.get(url, timeout=10)
print(response.status_code)
print(response.text[:100])

2.requests + StringIO — the reliable way into pandas

StringIO lets pandas treat downloaded text as if it were a local file. This is the method to reach for by default.

import pandas as pd
from io import StringIO

df = pd.read_csv(StringIO(response.text))
print(df.head())
print(len(df), "rows")

3.pd.read_csv(url) directly — shorter, not always reliable

pandas can fetch a URL itself. It often works — but it uses your system's own certificate setup, not requests' bundled one, and can fail with an SSL error on some machines even when requests.get() on the same URL is fine. Section 2's method always works instead.

# df = pd.read_csv(url)
# SSL: CERTIFICATE_VERIFY_FAILED  <- can happen here even though
#                                    requests.get(url) worked above

4.Kaggle, and your own hosted data

Kaggle needs an account and an API token (pip install kaggle, then kaggle datasets download -d owner/name) — not a single requests.get(). But once it is a .csv on disk, everything from here works the same. A CSV you commit to your own GitHub repo works exactly like Topic 2's example — same mechanism, nothing special about who owns it.

Same idea, three fields

Field Looks like
AI / Data Science downloading a Kaggle dataset for analysis
Cyber Security downloading a public breach or phishing-domain list
IT downloading a public device/config inventory file

Common mistakes

Mistake What you see Fix
using the blob (web page) URL instead of raw HTML, not data swap blob for raw, use raw.githubusercontent.com
pd.read_csv(url) failing with an SSL error SSL: CERTIFICATE_VERIFY_FAILED use requests + StringIO instead
forgetting StringIO and passing response.text straight to read_csv TypeError wrap it: StringIO(response.text)
assuming Kaggle is one line like a raw URL stuck without an account/token Kaggle needs pip install kaggle and a token first

Part 3

Light Regex

Official docs: re module

Week 7's string methods need to know the exact text. This week: finding something by its shape instead.

1.Why Week 7's tools are not enough here

"Does this contain an IP address" is not "does this contain one exact substring" — the IP is different every time.

import re

line = "2026-09-08 connection from 10.0.0.5 refused"

match = re.search(r"\d+\.\d+\.\d+\.\d+", line)
print(match.group())

2.re.search() returns None when nothing matches

Same shape as Week 7's .find() returning -1 — check before you use it.

no_ip = "no address in this line"
match = re.search(r"\d+\.\d+\.\d+\.\d+", no_ip)
print(match)

if match:
    print(match.group())
else:
    print("no IP found")

3.re.findall() — every match, as a list

log = "attempts from 10.0.0.5 and 192.168.1.1 and 10.0.0.9"
all_ips = re.findall(r"\d+\.\d+\.\d+\.\d+", log)
print(all_ips)

4.A second pattern, and using it on real pulled data

date_match = re.search(r"\d{4}-\d{2}-\d{2}", line)
print(date_match.group())

sample = "Supports Python 3.12 and above, tested on 3.10 too"
print(re.findall(r"\d+\.\d+", sample))

5.Capture groups — pulling out the pieces, not just the whole match

Parentheses (...) in a pattern mark a "capture group" — a part of the match you want separately, not just confirmed as present.

log_line = "2026-09-08 ERROR connection from 10.0.0.5"

match = re.search(r"(\d{4}-\d{2}-\d{2}) (\w+)", log_line)
print(match.group(0))   # the whole match: 2026-09-08 ERROR
print(match.group(1))   # just the date:   2026-09-08
print(match.group(2))   # just the level:  ERROR

Named groups — (?P<name>...) — read back much more clearly than counting parentheses:

match = re.search(r"(?P<date>\d{4}-\d{2}-\d{2}) (?P<level>\w+)", log_line)
print(match.group("date"))     # 2026-09-08
print(match.group("level"))    # ERROR

6.re.sub() — find and replace by shape

Same idea as Week 7's .replace(), but matching a shape instead of exact text — useful for redacting anything that looks like sensitive data.

text = "Server IP: 192.168.0.10, DNS: 8.8.8.8, Gateway: 10.0.0.1"

redacted = re.sub(r"\d+\.\d+\.\d+\.\d+", "[REDACTED]", text)
print(redacted)

Same idea, three fields

Field Looks like
AI / Data Science pulling every number out of a free-text survey answer
Cyber Security pulling every IP address out of a raw log file
IT pulling a version number or hostname pattern out of free-text config

Common mistakes

Mistake What you see Fix
calling .group() without checking for None first AttributeError: 'NoneType' object has no attribute 'group' if match: before using it
using re.search() when you want every match only the first one comes back use re.findall() instead
forgetting the r before the pattern string usually still works here, but backslashes can misbehave without it always write r"..." for a regex pattern
a pattern that is too loose or too strict matches the wrong thing, or nothing at all test it on a few real examples before trusting it
match.group(1) on a pattern with no (...) IndexError: no such group group(1) needs a capture group in the pattern first

Part 4

From Functions to a Class

Official docs: Python tutorial: classes · Requests quickstart

The same refactor Week 5's demo did to record_check.py. This time you do it to your own code.

1.Before: loose functions and a stray variable

def parse_line(raw_line):
    """Turn one messy raw line into a dict."""
    label, value = raw_line.strip().split(",")
    return {"label": label.strip().lower(), "value": float(value)}

def status_of(value, limit=100):
    """Return OVER LIMIT or OK for a value against a limit."""
    return "OVER LIMIT" if value >= limit else "OK"

over_limit_count = 0   # <- not attached to anything

2.After: one class, bundling the same data and logic

Nothing here is new — every line is something Week 5 already taught. What changed is where it lives.

class RecordSource:
    """Loads raw lines, parses them, and tracks how many are over limit."""

    def __init__(self, limit=100):
        self.limit = limit
        self.records = []
        self.over_limit_count = 0

    def parse_line(self, raw_line):
        label, value = raw_line.strip().split(",")
        return {"label": label.strip().lower(), "value": float(value)}

    def status_of(self, value):
        return "OVER LIMIT" if value >= self.limit else "OK"
before: loose functions            after: one class

parse_line(raw_line)                class RecordSource:
status_of(value, limit)                 self.limit
over_limit_count  (stray)               self.over_limit_count
                                         def parse_line(self, raw_line): ...
                                         def status_of(self, value): ...

same logic - now it travels together, and two RecordSource objects
never interfere with each other

3.What actually changed

over_limit_count can no longer be forgotten or reset by accident — it belongs to the object. parse_line and status_of no longer need their inputs passed between calls — they share self. You can now make a second RecordSource with a different limit, and the two will not interfere.

a = RecordSource(limit=100)
b = RecordSource(limit=50)
print(a.limit, b.limit)   # independent

Same idea, three fields

Field Looks like
AI / Data Science a Dataset class bundling loading, cleaning and summarising
Cyber Security an IncidentLog class bundling loading, parsing and flagging
IT an OpsConsole class bundling fetching, checking and reporting

Common mistakes

Mistake What you see Fix
forgetting to change value to self.value when moving a function in NameError or wrong result every reference to shared data needs self.
leaving limit as a function parameter instead of self.limit works, but defeats the point — nothing is bundled store it in __init__, read it via self
one class doing everything with no clear responsibility hard to test, hard to extend keep it to the same "one job" rule as functions had
reaching for inheritance or a second class more complexity than this project needs yet one or two classes is the whole ask this week
