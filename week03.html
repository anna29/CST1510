Part 1

Defining and Calling Functions

Official docs: Defining functions

Copy-pasting the same block twice is the sign you need one of these.

1.def creates it, calling runs it

Defining a function does not run it. Nothing happens until you call it — and you can call it as many times as you like.

def greet():
    print("Record check starting")

greet()
greet()

2.A parameter lets you pass something in

def greet_record(record_id):
    print(f"Checking {record_id}")

greet_record("srv-01")
greet_record("srv-02")

3.return sends a value back out

print() shows something. return gives something back to use.

def add_tax(price):
    return price * 1.2

total = add_tax(100)
print(total)
       percent_of(87, 100)
              │
     ┌────────┴────────┐
     │ part=87 total=100 │   <- parameters are just local names
     └────────┬────────┘
              │
      return (part / total) * 100
              │
              ▼
            87.0              <- comes back out here, to wherever you put it

4.Why functions

One job each. Fix the calculation in one place, and every call is fixed — instead of hunting down every copy you pasted it into.

A one-line string right after def, before any code, documents what the function does. Python treats it specially — this is called a docstring.

def percent_of(part, total):
    """Return part as a percentage of total."""
    return (part / total) * 100

help(percent_of)

Same idea, three fields

Field Looks like
AI / Data Science clean(row) — one job, reused for every row
Cyber Security is_suspicious(ip) — one check, reused for every log line
IT ping(host) — one action, reused for every server

Common mistakes

Mistake What you see Fix
forgetting () when calling — greet not greet() nothing happens, or you see <function greet at ...> add the brackets
printing inside a function instead of returning works once, breaks the moment you need the value again decide: does this function show, or give back?
expecting a value without catching it — add_tax(100) on its own the returned value is thrown away total = add_tax(100)
defining a function but never calling it nothing happens, no error def alone does nothing — you must call it
a docstring that just repeats the function's name technically legal, tells you nothing say what it does, not what it's called

Part 2

Parameters and Arguments

Official docs: More on defining functions

Real functions take more than one input, and not every input needs to be given every time.

1.Multiple parameters, matched by position

def within_limit(value, limit):
    return value <= limit

print(within_limit(87, 100))
print(within_limit(100, 87))   # swapped - a different answer

2.A default value is a fallback

Give a parameter = something in the def line, and callers can leave it out.

def status_of(percent, warning_at=90):
    if percent >= 100:
        return "OVER LIMIT"
    elif percent >= warning_at:
        return "WARNING"
    else:
        return "OK"

print(status_of(95))       # uses the default, 90
print(status_of(95, 96))   # overrides it

3.Keyword arguments

Name which parameter you are filling in. Order stops mattering, and the call site becomes readable on its own.

print(status_of(percent=95, warning_at=90))
print(status_of(warning_at=90, percent=95))   # same result, reordered

4.Mixing positional and keyword

Positional arguments must come first. Once you use a keyword, everything after it must be a keyword too.

print(status_of(95, warning_at=90))    # fine
# print(status_of(percent=95, 90))    # SyntaxError

5.*args and **kwargs — when you don't know how many

Sometimes you don't know in advance how many arguments will be passed. *args collects any extra positional arguments into a tuple; **kwargs collects extra keyword arguments into a dict. The names args/kwargs are just convention — the * and ** are what actually matter.

def total(*numbers):
    return sum(numbers)

print(total(1, 2, 3))          # 6
print(total(10, 20, 30, 40))   # 100
total(1, 2, 3)
        │
        ▼
   numbers = (1, 2, 3)     - a tuple, built for you, however many you passed

**kwargs does the same job for keyword arguments, collecting them into a dict.

def configure(**settings):
    for key, value in settings.items():
        print(f"{key} = {value}")

configure(host="10.0.0.1", port=8080, ssl=True)

Same idea, three fields

Field Looks like
AI / Data Science load(path, header=True)
Cyber Security scan(target, timeout=5)
IT backup(source, destination="/backups")

Common mistakes

Mistake What you see Fix
a required parameter after a default one SyntaxError defaults must come last in the def line
a positional argument after a keyword one SyntaxError positional first, keyword after
relying on position with many parameters wrong value in the wrong place, no error use keywords once you have three or more
passing too few arguments TypeError: missing ... required positional argument check the def line for what it actually needs
forgetting *args arrives as a tuple, not separate variables numbers[0] works, numbers alone is not one number loop over it, or index into it — it's one collection

Part 3

Scope

Official docs: Python scopes and namespaces

A function's own variables do not leak out. The outside world's variables do not leak in by accident, either.

1.Local means local

A variable created inside a function only exists inside it.

def check():
    result = "OK"
    print(result)

check()

# print(result)   # NameError: name 'result' is not defined
outside
   │
   ├── calls check()
   │        │
   │        ▼
   │   result = "OK"    (created here, local only)
   │        │
   │        ▼
   │   check() ends — result stops existing
   │
   └── print(result) ──▶  NameError. It never existed out here.

2.Parameters are local too

def double(n):
    n = n * 2
    return n

number = 21
print(double(number))   # 42
print(number)             # still 21 - the n inside double is its own copy

3.Reading an outer variable is fine. Changing it is not.

A function can read a variable defined outside it. It cannot change your copy of it — only give you back a new value, which you choose whether to keep.

def add_tax(price):
    price = price * 1.2   # only changes the LOCAL copy
    return price            # this is what actually gets it out

total = 100
total = add_tax(total)   # catch it and reassign
print(total)               # 120.0

4.Returning more than one value

return is not limited to one value. Separate them with commas, and unpack them into names on the way back out, in the same order.

def check_record(value, limit):
    difference = value - limit
    percent = (value / limit) * 100
    return difference, percent

difference, percent = check_record(87, 100)
print(difference, percent)

5.The wall is the point, not a limitation

Because a function cannot reach outside itself, calling it can never accidentally break something unrelated elsewhere in the program. Everything it needs comes in as a parameter. Everything it produces goes out via return. That is the whole contract — and it is what makes a function safe to call from anywhere.

Same idea, three fields

Field Looks like
AI / Data Science a cleaning function cannot silently corrupt the original dataset
Cyber Security a scanning function cannot silently alter the system it is checking
IT a status-check function cannot silently change the server it is reporting on

Common mistakes

Mistake What you see Fix
using a variable created inside a function, outside it NameError return it, and catch the result outside
expecting a function to change a variable you passed in the outside variable is unchanged return the new value and reassign it yourself
assuming an error will warn you when a change is silently lost no error at all — the bug is quiet this is exactly why you return and reassign explicitly
unpacking into the wrong number of names ValueError: too many values to unpack (or not enough) the number of names must match the number of returned values, in order

Part 4

Modules

Official docs: Modules

Not every function has to be one you wrote. This is how you use one that is already there.

1.import brings in a whole module

Access what is inside it with a dot.

import math

print(math.sqrt(16))
print(math.pi)
print(math.ceil(4.2))
print(math.floor(4.8))

2.random — another module in the standard library

import random

print(random.randint(1, 6))
print(random.choice(["OK", "WARNING", "OVER LIMIT"]))

3.from module import name

Brings in one specific name directly — no dot needed afterwards. Convenient, but a reader can no longer tell at a glance which module it came from.

from math import sqrt

print(sqrt(16))   # not math.sqrt(16)

4.Standard library vs installed

math and random ship with Python — nothing to install. pandas, which you will meet soon, does not — that needs pip install pandas first. The import keyword is the same either way; only where the module came from differs.

A module is really just a file of functions someone already wrote. You are already writing the wiring yourself — a module is wiring somebody else built, that you get to reuse.

5.Making your own file both a module and a script

Every mini-project you write is a .py file — which makes it a module too. If someone else imports it, Python runs every top-level line immediately, including any test print()s you left in. The __name__ == "__main__" guard lets you say "only run this part when this file is launched directly."

def area_of_circle(radius):
    return math.pi * radius ** 2

if __name__ == "__main__":
    print(area_of_circle(5))
python this_file.py         ──▶  __name__ is "__main__"   ──▶  the block runs
import this_file             ──▶  __name__ is "this_file"    ──▶  it does NOT run

The function definition above the guard runs either way — only the code inside the if is skipped when the file is imported instead of run.

Same idea, three fields

Field Looks like
AI / Data Science import statistics for mean, median
Cyber Security import hashlib for hashing a password
IT import datetime for timestamping a log entry

Common mistakes

Mistake What you see Fix
misspelling the module name — import maths ModuleNotFoundError: No module named 'maths' it is math, no s
calling sqrt(16) after import math (not from) NameError either math.sqrt(16) or from math import sqrt
a from import overwriting your own variable of the same name wrong value, no error check your variable names against what you are importing
forgetting the module needs installing ModuleNotFoundError for a real package name pip install <package> first, then import
test code at the top level, no __name__ guard it runs every time someone imports your file, not just when you run it put it inside if __name__ == "__main__":
