CST1510

Setup Guide

Seven steps, once, before Week 1. Choose Windows, macOS or Linux below and the commands will match your computer.

1. Install three things

  • Python from python.org/downloads. On the first screen, tick Add python.exe to PATH.
  • VS Code from code.visualstudio.com. Then open Extensions (Ctrl + Shift + XCmd + Shift + X) and install Python and Jupyter, both by Microsoft.
  • Git from git-scm.com/downloads, accepting the defaults.

On Ubuntu or Debian, install Python, Git and the notebook kernel in one go:

sudo apt update
sudo apt install python3 python3-venv python3-ipykernel git

(On other distributions, install the same packages with your package manager, e.g. dnf.)

Then install VS Code from code.visualstudio.com (the .deb file on Ubuntu or Debian). Open Extensions (Ctrl + Shift + X) and install Python and Jupyter, both by Microsoft.

2. Create your GitHub repository

Create a free account at github.com. Then click + (top right) → New repository, name it CST1510, tick Add a README file, and click Create repository.

3. Clone it into Documents

Open PowerShellTerminalTerminal (Ctrl + Alt + T) and run:

git config --global user.name "Your Name"
git config --global user.email "you@example.com"
cd Documents
git clone https://github.com/YOUR-USERNAME/CST1510.git

Use your own name, the email from your GitHub account, and your GitHub username. This creates the folder Documents/CST1510.

To check your Git settings at any time:

git config --list

Look for user.name and user.email in the list. Press q to exit if the list fills the screen.

4. Open the folder in VS Code

File → Open Folder → CST1510, then Terminal → New Terminal. Use this terminal from now on.

Check which branch you're on and that it's linked to GitHub:

git branch -vv

You should see * main followed by [origin/main]. That means you're on the main branch and it's linked to your repository on GitHub.

Every week's folder from Moodle goes inside CST1510, starting with the Week 00 folder.

5. Add a .gitignore file

This tells Git which files never to upload. In VS Code, create a new file in the CST1510 folder, name it .gitignore (starting with a dot), paste this in and save:

# Learning material: only each week's LAB folder is uploaded
Week */*
!Week */LAB/

# Files that should never be uploaded
.venv/
__pycache__/
.ipynb_checkpoints/
__MACOSX/
.DS_Store
.env

The first three lines mean only your LAB folders are uploaded each week. The rest of each week's folder is learning material and stays on your computer.

6. Make a test file

Create hello.py in the CST1510 folder:

print("Hello from CST1510!")

Run it:

python hello.py
python3 hello.py

7. Push it to GitHub

git add .
git commit -m "Week 0 setup"
git push

The first time, VS Code asks you to sign in to GitHub: click Allow and follow the browser window. Then open your repository on GitHub and check hello.py and .gitignore are there.

Done. Every week from now on, finish the lab with the same three commands. The Git and GitHub Guide explains them.

If something goes wrong

ProblemFix
python not found (Windows)Reinstall Python and tick Add python.exe to PATH.
python3 opens the Microsoft Store (Windows)Use python on Windows.
fatal: not a git repositoryOpen the CST1510 folder in VS Code and use its terminal.
externally-managed-environment when installing ipykernel (Linux)Install it with apt instead: sudo apt install python3-ipykernel (step 1).
A notebook won't runClick Select Kernel (top right) and click Install if asked about ipykernel.

Week 7: virtual environment and packages

You don't need this until Week 7.

1. Create the environment and install the packages in the VS Code terminal:

python -m venv .venv
.venv\Scripts\activate
python -m pip install -r "Week 00 - Orientation and Setup/requirements.txt"
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r "Week 00 - Orientation and Setup/requirements.txt"

2. Tell VS Code to use it: Ctrl + Shift + PCmd + Shift + P → Python: Select Interpreter → pick .venv. In notebooks, Select Kernel → .venv.

3. Check it:

python "Week 00 - Orientation and Setup/verify_setup.py"

Every line should say OK. Then push as usual.

If Windows says running scripts is disabled, run Set-ExecutionPolicy -Scope CurrentUser RemoteSigned, answer Y, and try again.
