Topic 1

Lists

Official docs: Lists · More on lists

1.Creating a list, and indexing

Every value you have stored so far has gone into one variable holding one value. A list holds many values in a single variable, in order. Formally, a list is Python's built-in sequence type: an ordered, mutable collection of items, written between square brackets and separated by commas. It is also a compound data type — a type whose whole purpose is to hold other values (including other lists), as opposed to a scalar type like int or float, which holds exactly one value.

"Ordered" has a precise meaning here: it is not that the items are sorted, but that each one has a fixed position, counted from 0 — the same rule range() already taught you. That position is what indexing reads.

labels = ["R-001", "R-002", "R-003"]
print(type(labels))   # <class 'list'>

print(labels[0])
print(labels[1])
print(labels[2])
Output<class 'list'>
R-001
R-002
R-003
index:     0        1        2
labels:  ["R-001", "R-002", "R-003"]
            ▲                  ▲
        labels[0]          labels[-1]

Indexing past the end is not silently ignored: labels[3] raises IndexError immediately — the last valid index is always len(labels) - 1. A list may also hold a mix of types (["R-001", 87.0, True] is legal), but in practice you keep one list's items the same type — the code that later loops over it stays predictable that way.

2.Negative indexing

Counts from the end. labels[-1] is the last item, whatever the length turns out to be — no need to know how many items there are. For a list of length n, valid indices run from 0 to n - 1 counting forward, and from -1 to -n counting backward — labels[0] and labels[-n] always name the same item.

print(labels[-1])   # R-003
print(labels[-2])   # R-002
print(len(labels))   # 3
OutputR-003
R-002
3

Same rule as range(start, stop) — stop is never included.

print(values[2:])     # [30, 40, 50]

4.Changing, adding and removing

Because a list is mutable, all three of these change the same list object in place — no new list is created, and no reassignment is needed.

Changing an item uses the same index syntax as reading one, on the left of =. Adding one item to the end uses .append(). Removing uses .remove(value), which deletes the first match by value and raises ValueError if that value is not present.

values[0] = 99          # change, by index
values.append(60)      # add, to the end
values.remove(20)      # remove, by value - first match only
print(values)

for v in values:   # for loops directly over the values, no counting needed
    print(v)
Output[99, 30, 40, 50, 60]
99
30
40
50
60

Python also has .pop(), which removes by position instead of by value: values.pop(0) removes and returns the first item, and plain values.pop() removes the last one. Reach for .remove() when you know the value; reach for .pop() when you know the position and want it back.

5.Membership — in and not in

Before searching a list by hand with a loop, check whether Python already has an operator for the job — for a yes/no question like "is this value present", it does. in and not in are membership operators: they test whether a value occurs in a sequence and return a bool, without you writing the search yourself.

OperatorReturns
value in sequenceTrue if value is found
value not in sequenceTrue if value is not found
due_tonight = ["srv-01", "srv-02", "srv-03"]

print("srv-02" in due_tonight)        # True
print("srv-09" not in due_tonight)    # True

if "srv-09" in due_tonight:
    print("already scheduled")
else:
    print("srv-09 not scheduled yet")
OutputTrue
True
srv-09 not scheduled yet

This is also the safe way to guard .remove(): check if value in a_list: before removing it, and the ValueError from section 4 never happens.

6.Aliasing — two names, one list

A list variable does not hold the list itself — it holds a reference to it, wherever in memory it actually lives. Assigning one list variable to another (backup = hosts) copies the reference, not the data: both names now point at the exact same list object. This is called aliasing, and because lists are mutable, it has a real consequence — a change made through either name is visible through both.

hosts = ["srv-01", "srv-02"]
backup = hosts          # backup is another name for the SAME list

backup.append("srv-03")
print(hosts)              # ['srv-01', 'srv-02', 'srv-03'] - changed too!
print(hosts is backup)     # True - literally the same object
Output['srv-01', 'srv-02', 'srv-03']
True
hosts  ──┐
         ├──▶  ["srv-01", "srv-02", "srv-03"]   <- one list object
backup ──┘

hosts = ["srv-01", "srv-02"]      <- reassigning hosts instead
backup = hosts                    <-   makes a NEW list; backup still
hosts = ["srv-09"]                <-   points at the old one - the link
                                        breaks the moment you reassign,
                                        not when you mutate

Contrast this with hosts = ["srv-09"] (reassignment, not mutation): that makes hosts point at a brand-new list, leaving backup pointing at the old one — the alias only matters while both names keep pointing at the same object. This is also exactly why a tuple or a string being immutable is a genuine safety feature, not just a restriction: aliasing two names to the same tuple can never surprise you, because neither name can change what it points to. Topic 2 leans on this same idea from the other direction — it is precisely because tuples and strings cannot change that Python is willing to use them as dictionary keys.

If you need an independent copy rather than another name for the same list, use backup = hosts.copy() (or hosts[:]) instead of plain =.

7.Tuples — like a list, but locked

Same idea, () instead of []. Indexing and slicing work exactly the same way — but a tuple is immutable: it cannot be changed after it is created. No .append(), no changing an item, and — as section 6 just showed — no risk of an alias surprising you either.

You have already used one. Week 3's return difference, percent, status sent back a tuple — three values as one — and difference, percent, status = check_record(...) unpacked it into three names.

point = (3, 7)
print(point[0])   # 3 - indexing works the same as a list

8.Strings slice the same way too

You have been indexing and slicing without knowing it since Week 1. A string follows the exact same rules as a list — and like a tuple, it is locked.

record_id = "R-001"

print(record_id[0])       # 'R' - same indexing rule
print(record_id[-1])      # '1' - same negative indexing
print(record_id[0:2])     # 'R-' - same slicing rule, stop excluded
print(record_id[-3:])     # '001'
OutputR
1
R-
001

Same lock as a tuple — you can read a character, not change one in place. The full toolbox of string methods (.upper(), .strip(), .replace() and more) is coming properly in Week 7. For now: the shape you already know for lists and tuples works on text too.

Topic 2

Dictionaries

Official docs: Dictionaries · Sets

1.Creating and accessing

A list finds things by position. A dictionary finds things by name.

record = {
    "label": "R-001",
    "value": 87.0,
    "limit": 100.0,
}

print(record["label"])
print(record["value"])
OutputR-001
87.0

2.Adding and updating

The same line does both — if the key exists, it updates; if not, it adds.

record["status"] = "OK"     # new key
record["value"] = 90.0        # existing key, updated
print(record)
Output{'label': 'R-001', 'value': 90.0, 'limit': 100.0, 'status': 'OK'}

3.Missing keys, and .get()

record["missing"] raises KeyError. .get() does not — it gives you None, or a default of your choosing.

print(record.get("status"))            # OK
print(record.get("missing"))           # None
print(record.get("missing", "n/a"))    # n/a
OutputOK
None
n/a

4.Iterating

.items() gives you both the key and the value together — the one you will use most.

for key, value in record.items():
    print(f"{key}: {value}")

5.Sets — only unique values, in curly braces too

Created with {"{a, b, c}"} — or set() for an empty one. Not {"{}"}: that makes an empty dict, not an empty set. No order, no indexing, and duplicates are dropped automatically.

labels = ["R-001", "R-002", "R-001", "R-003"]
unique_labels = set(labels)

print(unique_labels)             # duplicates gone
print(len(unique_labels))       # 3, not 4
print("R-001" in unique_labels)   # True - fast membership check

empty_set = set()   # NOT {} - that is an empty dict
Output{'R-001', 'R-002', 'R-003'}
3
True

Topic 3

Files

Official docs: Reading and writing files · open()

1.Writing, with with

Everything so far disappears the moment the program ends. A file does not. with ... as f: opens the file, hands you f to work with, and closes it automatically when the indented block ends — even if something goes wrong partway through.

with open("output.txt", "w") as f:
    f.write("R-001\n")
    f.write("R-002\n")
with open("output.txt", "w") as f:

       ▼
  file is open, f is your handle
       │
       ▼
  ... f.write(...) ...
       │
       ▼
  block ends  ──▶  file closes automatically, even if an error happened

Looping over an open file gives you one line at a time — the natural way to process many records. Each line keeps its trailing \n — .strip() removes it.

2.Loading it from a file

Topic 3's load_records — the line-reading and splitting you already wrote, now building the list up one dict at a time.

def load_records(path):
    """Read label,value,limit lines from a file and return a list of dicts."""
    records = []
    with open(path) as f:
        for line in f:
            label, value, limit = line.strip().split(",")
            records.append({"label": label, "value": float(value), "limit": float(limit)})
    return records

The loop looks the same whether the list came from Topic 1's by-hand version or Topic 3's file — that consistency is the point.

for record in records:

    print(f"{record['label']}: {status}")
