Topic 1

Comparisons and Boolean Logic

1.The six comparison operators

Each one asks a question and answers with True or False: == equal to, != not equal to, > greater than, < less than, >= at least, <= at most.

value = 23.7
limit = 20

print(value == limit)
print(value > limit)
print(value <= limit)
OutputFalse
True
False

2.= stores, == asks

This is the single most common slip this week. = puts a value in. == checks one. They read almost the same and do completely different things.

limit = 20          # gets: "limit now holds 20"
print(limit == 20)  # asks: "does limit hold 20?"
OutputTrue
Practice

Given checks_done = 10, write the line that asks whether checks_done is 10 — not the one that changes it.

3.A comparison is a value too

The result has a type of its own: bool. You can store it, just like anything else.

is_over = value > limit

print(is_over)
print(type(is_over))
OutputTrue
<class 'bool'>

4.Combining conditions

and — both sides must be True. or — at least one side. not — flips it. Bracket each comparison when you combine them: it costs nothing and removes all doubt.

percent = 95.0

print((percent >= 90) and (percent < 100))
print(not (percent < 90))
OutputTrue
True

Topic 2

if, elif, else

1.if

The indented block only runs when the condition is True. Nothing special happens when it is False — Python just moves on.

if value > limit:
    print("OVER")
OutputOVER
Practice

Given attempts = 3, write an if that prints LOCKED when attempts >= 3.

2.else

Runs when the if condition was False. Exactly one of the two branches runs — never both, never neither.

if value > limit:
    print("OVER")
else:
    print("OK")
OutputOVER
check: value > limit ?
   │
   ├── True  ──▶ print("OVER")
   │
   └── False ──▶ print("OK")
Practice

Given attempts = 2, write an if / else that prints LOCKED when attempts >= 3, otherwise OK.

3.elif

Checked top to bottom. The first True one runs, and the rest are skipped — even if they are also True. Put the most specific condition first.

percent = 105.0

if percent >= 100:
    status = "OVER LIMIT"
elif percent >= 90:
    status = "WARNING"
else:
    status = "OK"

print(status)
OutputOVER LIMIT
check: percent >= 100 ?
   │
   ├── True  ──▶ status = "OVER LIMIT"        (done - the rest is skipped)
   │
   └── False ──▶ check: percent >= 90 ?
                    │
                    ├── True  ──▶ status = "WARNING"   (done)
                    │
                    └── False ──▶ status = "OK"

Each elif only runs if every check above it was False. The moment one branch fires, the rest are skipped — that is why order matters.

Practice

A server's disk_used_pct is 72. Print CRITICAL if at or above 90, WARNING if at or above 75, otherwise OK.

4.Indentation is syntax, not style

Python has no { }. The indented lines are the block. Miss it, and Python does not guess what you meant — it stops.

if value > limit:
    print("checking...")   # part of the if
    print("OVER")           # part of the if
print("done")                # NOT indented - runs either way
Outputchecking...
OVER
done

Write an if / elif / else where every keyword lines up in the same column, each with two indented lines inside it.

Topic 3

while Loops

1.while

Repeats the block while the condition is True. Same indentation rule as if.

count = 1

while count <= 3:
    print(count)
    count += 1

print("done")
Output1
2
3
done
check: count <= 3 ?
   │
   ├── True  ──▶ print(count)  ──▶  count += 1  ──▶  back to check
   │
   └── False ──▶ done

Follow the arrows. The loop only ends when the path reaches False — which is exactly why count += 1 has to be inside the loop. Leave it out and every lap takes the True branch, forever.

Practice

Print hello 5 times using a counter and while.

2.The condition must change, or it never stops

Every error so far has printed a message and stopped. An infinite loop does neither — the program is just still running. If it happens to you: interrupt the kernel, do not wait it out.

count = 1
while count <= 3:
    print(count)
# count is never updated, so the condition is True forever

Read this — do not run it. Say out loud what line is missing, and what it should do, before moving on.

3.while True: + break

Loop until something inside the loop decides to stop, instead of counting in advance. This is what you use when you do not know how many times you will repeat.

while True:
    answer = input("Another? (y/n): ")
    if answer == "n":
        break
    print("okay, again")

4.break and continue

break exits the loop immediately. continue skips the rest of this pass and goes straight back to checking the condition.

n = 0
while n < 5:
    n += 1
    if n == 3:
        continue     # skip printing 3
    print(n)
Output1
2
4
5

Topic 4

for Loops and range

1.for i in range(n)

Repeats exactly n times. i takes 0, 1, 2, ... up to but not including n.

for i in range(5):
    print(i)
Output0
1
2
3
4
for i in range(5):
      i takes, in order:   0 ──▶ 1 ──▶ 2 ──▶ 3 ──▶ 4
      the indented block runs once for each value, then the loop just ends
      - no condition to check, no risk of it running forever
Practice

Print Record 1 through Record 5 — not Record 0 through Record 4.

2.range(start, stop)

stop is never included. This is where most for mistakes happen.

for i in range(1, 6):
    print(i)   # 1 2 3 4 5

for i in range(1, 5):
    print(i)   # 1 2 3 4 - not 5
Output1

Print the numbers 1 to 10, inclusive.

4.for vs while

Know the count in advance → for. Waiting on a condition or a signal → while (Topic 3). for can loop a fixed number of records even before you have a real list of them to loop over — Week 4 will replace range(n) with the real data.

for i in range(3):
    value = float(input("Value: "))
    print(value)
