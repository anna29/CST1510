Part 1

Comparisons and Boolean Logic

Official docs: Truth value testing · Boolean operations

This is where a program starts asking questions about what it stored.

1.The six comparison operators

Each one asks a question and answers with True or False.

== equal to · != not equal to · > greater than · < less than · >= at least · <= at most

Run the next cell.

value = 23.7
limit = 20

print(value == limit)
print(value > limit)
print(value <= limit)

2.= stores, == asks

This is the single most common slip this week. = puts a value in. == checks one.

They read almost the same and do completely different things.

limit = 20          # gets: "limit now holds 20"
print(limit == 20)  # asks: "does limit hold 20?"

3.A comparison is a value too

The result has a type of its own: bool. You can store it, just like anything else.

is_over = value > limit

print(is_over)
print(type(is_over))

4.Combining conditions

and — both sides must be True. or — at least one side. not — flips it.

Bracket each comparison when you combine them. It costs nothing and removes all doubt.

percent = 95.0

print((percent >= 90) and (percent < 100))
print(not (percent < 90))

Same idea, three fields

A comparison is the universal "does this cross a line?" check.

Field Looks like
AI / Data Science missing_pct > 5 — is the missing-data rate too high?
Cyber Security failed_logins >= 3 — should this account be locked?
IT disk_used_pct >= 90 — is storage nearly full?

Different job, same tool.

Common mistakes

Mistake What you see Fix
value = 20 when you meant to ask nothing — it silently reassigns use == to ask, = to store
"20" == 20 False text and number are never equal — check the type
forgetting brackets in a combined condition wrong answer, no error bracket each comparison
if 90 <= percent <= 100 before you are confident works, but confusing this early write percent >= 90 and percent <= 100 until you are sure

Part 2

if, elif, else

Official docs: The if statement

Booleans decide something is true. This is where the program acts on it.

1.if

The indented block only runs when the condition is True. Nothing special happens when it is False — Python just moves on.

value = 23.7
limit = 20

if value > limit:
    print("OVER")

2.else

Runs when the if condition was False. Exactly one of the two branches runs — never both, never neither.

if value > limit:
    print("OVER")
else:
    print("OK")

3.elif

Checked top to bottom. The first True one runs, and the rest are skipped — even if they are also True. Put the most specific condition first.

percent = 105.0

if percent >= 100:
    status = "OVER LIMIT"
elif percent >= 90:
    status = "WARNING"
else:
    status = "OK"

print(status)

4.Indentation is syntax, not style

Python has no { }. The indented lines are the block. Miss it, and Python does not guess what you meant — it stops.

if value > limit:
    print("checking...")   # part of the if
    print("OVER")           # part of the if
print("done")                # NOT indented - runs either way

Same idea, three fields

Field Looks like
AI / Data Science if missing_pct > 5: print("check pipeline")
Cyber Security if failed_logins >= 3: print("LOCKED")
IT if disk_used_pct >= 90: print("ALERT")

Common mistakes

Mistake What you see Fix
missing : SyntaxError every if / elif / else line ends with :
next line not indented IndentationError indent consistently — 4 spaces
if x = 5: SyntaxError you meant ==
broad condition checked before the specific one wrong branch runs, no error order elif chains most-specific first

Part 3

while Loops

Official docs: The while statement

So far your program runs once, top to bottom. This is how it repeats.

1.while

Repeats the block while the condition is True. Same indentation rule as if.

count = 1

while count <= 3:
    print(count)
    count += 1

print("done")
check: count <= 3 ?
   │
   ├── True  ──▶ print(count)  ──▶  count += 1  ──▶  back to check
   │
   └── False ──▶ done

Follow the arrows. The loop only ends when the path reaches False — which is exactly why count += 1 has to be inside the loop. Leave it out and every lap takes the True branch, forever.

2.The condition must change, or it never stops

Every error so far has printed a message and stopped. An infinite loop does neither — the program is just still running. If it happens to you: interrupt the kernel, do not wait it out.

Read this — do not run it:

count = 1
while count <= 3:
    print(count)
# count is never updated, so the condition is True forever

3.while True: + break

Loop until something inside the loop decides to stop, instead of counting in advance. This is what you use when you do not know how many times you will repeat.

while True:
    answer = input("Another? (y/n): ")
    if answer == "n":
        break
    print("okay, again")

4.break and continue

break exits the loop immediately. continue skips the rest of this pass and goes straight back to checking the condition.

n = 0
while n < 5:
    n += 1
    if n == 3:
        continue     # skip printing 3
    print(n)

Same idea, three fields

Field Looks like
AI / Data Science keep pulling batches while more data is available
Cyber Security keep checking log lines until a sentinel or end of file
IT keep checking a server's status until it responds healthy

Common mistakes

Mistake What happens Fix
forgetting to update what the condition checks runs forever make sure something inside the loop changes it
while count = 5: SyntaxError you meant ==, or while count < 5:
while True: with no break anywhere runs forever every while True: needs an exit
condition checks the wrong variable runs the wrong number of times, or never stops trace it by hand with real numbers first

Part 4

for Loops and range

Official docs: The for statement · Built-in range()

When you already know how many times to repeat, for says so directly.

1.for i in range(n)

Repeats exactly n times. i takes 0, 1, 2, ... up to but not including n.

for i in range(5):
    print(i)
for i in range(5):
      i takes, in order:   0 ──▶ 1 ──▶ 2 ──▶ 3 ──▶ 4
      the indented block runs once for each value, then the loop just ends
      - no condition to check, no risk of it running forever

2.range(start, stop)

stop is never included. This is where most for mistakes happen.

for i in range(1, 6):
    print(i)   # 1 2 3 4 5

for i in range(1, 5):
    print(i)   # 1 2 3 4 - not 5

3.range(start, stop, step)

Counting by more than one at a time — or counting down, with a negative step.

for i in range(10, 0, -1):
    print(i)   # 10 9 8 ... 1

4.for vs while

Know the count in advance → for. Waiting on a condition or a signal → while (Topic 3). for can loop a fixed number of records even before you have a real list of them to loop over — Week 4 will replace range(n) with the real data.

for i in range(3):
    value = float(input("Value: "))
    print(value)

5.enumerate() — the index, for free

Looping and needing to know which one you are on is common enough that Python has a shortcut — enumerate() hands you the position and the value together, so you never have to track a counter by hand.

for i, letter in enumerate("cat"):
    print(i, letter)
enumerate("cat")  ──▶  (0, 'c'), (1, 'a'), (2, 't')
                           │         │
                      position    value — both, at the same time

start= shifts where the counting begins — useful for human-friendly numbering, since people count from 1, not 0.

for i, letter in enumerate("cat", start=1):
    print(f"letter {i}: {letter}")

Same idea, three fields

Field Looks like
AI / Data Science process a fixed batch of n rows
Cyber Security check a fixed list of n known IPs
IT ping a fixed set of n servers

Common mistakes

Mistake What you see Fix
range(5) expecting 1–5 gives 0–4 starts at 0 unless you say otherwise
range(1, 5) expecting 1–5 gives 1–4 stop is never included — use range(1, 6)
using for when you do not know the count in advance only works if you guess right that is what while is for
changing i inside the loop, expecting it to affect the count no effect range() already decided every value in advance
for i in enumerate(x): — forgetting to unpack i is a whole (0, 'c') pair, not just the index unpack both: for i, value in enumerate(x):
