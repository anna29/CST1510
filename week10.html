2. `CREATE TABLE` — defining the shape

IF NOT EXISTS avoids an error if it is already there. PRIMARY KEY is a unique, auto-numbered row identifier.

Code
cursor.execute("""
    CREATE TABLE IF NOT EXISTS devices (
        id     INTEGER PRIMARY KEY,
        name   TEXT NOT NULL,
        ip     TEXT UNIQUE NOT NULL,
        active INTEGER DEFAULT 1
    )
""")
conn.commit()

3. Five storage classes — that is genuinely all of them

INTEGER, REAL, TEXT, BLOB, NULL. No separate date type — store dates as TEXT, ISO format (YYYY-MM-DD), so they still sort correctly.

Code
cursor.execute("""
    CREATE TABLE readings (
        id       INTEGER PRIMARY KEY,
        sensor   TEXT NOT NULL,
        value    REAL NOT NULL,
        recorded TEXT NOT NULL
    )
""")
conn.commit()

4. SQLite will not stop you being wrong

It is flexible about types — a string can land in a REAL column with no error at all. Your own code has to enforce what the schema will not.

Code
cursor.execute("INSERT INTO readings (sensor, value, recorded) VALUES (?, ?, ?)",
               ("temp-01", "not-a-number", "2026-09-08"))
conn.commit()

row = cursor.execute("SELECT value FROM readings").fetchone()
print(row, type(row[0]))    # stored as-is - no error, no warning
Your turn

Write a small function that converts a value to float before inserting it, so a bad value fails loudly instead of being stored silently.

Code

Code
rows = [("Switch-1", "10.0.0.2", "switch"), ("AP-Lobby", "10.0.0.3", "access point")]
cursor.executemany("INSERT INTO devices (name, ip, type) VALUES (?, ?, ?)", rows)
conn.commit()
Your turn

Use executemany() to insert 3 rows of your own choosing.

3. `fetchall()`, `fetchone()`, and iterating the cursor directly

Code
print(cursor.execute("SELECT * FROM devices").fetchall())
print(cursor.execute("SELECT name FROM devices WHERE id = ?", (999,)).fetchone())   # None, no crash

for name, ip in cursor.execute("SELECT name, ip FROM devices"):
    print(name, "->", ip)
Your turn

4. SQL injection — seeing it actually work, and actually get blocked

Building SQL by joining a string in is not a style choice — it is a real vulnerability.

Code
name = "' OR '1'='1"
unsafe = f"SELECT * FROM devices WHERE name = '{name}'"
print(cursor.execute(unsafe).fetchall())    # returns EVERY row - the WHERE did nothing

safe = cursor.execute("SELECT * FROM devices WHERE name = ?", (name,)).fetchall()
print(safe)    # empty - treated as data, not code
Your turn

Try your own malicious-looking string against both the unsafe and safe versions and compare the results.

Mistake What you see Fix
building SQL with an f-string and a real value SQL injection — a crafted value can return or destroy data it should not always use ? placeholders
forgetting the trailing comma on a single value ProgrammingError: Incorrect number of bindings supplied (value,) is a tuple; (value) is not

Updating, Deleting and the Safe Pattern

Box we are building: STORE, changed carefully

The one mistake in this topic affects every row in a table at once — worth slowing down for.

Already know this? Skip to the Topic 3 Challenge.

1. `UPDATE` — changing existing rows

Code
cursor.execute("UPDATE devices SET ip = ? WHERE id = ?", ("10.0.0.254", 1))
conn.commit()
print(cursor.execute("SELECT name, ip FROM devices WHERE id = 1").fetchone())
Your turn

Update one device's name, then confirm the change with a SELECT.

2. `rowcount` — how many rows actually changed

Code
result = cursor.execute("UPDATE devices SET active = 0 WHERE name = ?", ("AP-Lobby",))
conn.commit()
print(result.rowcount)
Your turn

Update a row and print how many rows rowcount says were affected.

3. `DELETE`, and the mistake that affects every row

A missing WHERE on UPDATE or DELETE changes or removes everything in the table — no confirmation, no undo.

Code
cursor.execute("DELETE FROM devices WHERE active = 0")
conn.commit()
print(cursor.execute("SELECT name FROM devices").fetchall())

# cursor.execute("DELETE FROM devices")
# -> wipes the WHOLE table. Always run the matching SELECT first.
Your turn

Run the matching SELECT for a DELETE you are about to write, and check the result looks right, before actually deleting.

4. The `with` pattern — commit and close, handled for you

Auto-commits on success. Auto-rolls-back if an error is raised inside the block — nothing half-finished gets saved.

Code
try:
    with sqlite3.connect("network.db") as c:
        c.execute("INSERT INTO devices (name, ip) VALUES (?, ?)", ("Duplicate", "10.0.0.254"))
except sqlite3.IntegrityError as e:
    print("Nothing was committed:", e)
Your turn

Rewrite one of Topic 2's inserts to use the with pattern instead of a manual commit().

Common mistakes

Mistake What you see Fix
UPDATE/DELETE with no WHERE every row changes or disappears always include WHERE, run the matching SELECT first
forgetting conn.commit() outside a with block the change silently does not persist commit explicitly, or switch to with
leaving a connection open resources leak in a long-running program close it, or use with so it happens automatically
assuming rowcount means something before commit() it is still accurate — the mistake is elsewhere, usually a missing commit after check commit happened, not just rowcount

1. `DataFrame.to_sql()` — the whole migration, one line

Code
import pandas as pd, requests
from io import StringIO

url = "https://raw.githubusercontent.com/mwaskom/seaborn-data/master/tips.csv"
df = pd.read_csv(StringIO(requests.get(url, timeout=10).text))

with sqlite3.connect("network.db") as conn:
    df.to_sql("tips", conn, if_exists="replace", index=False)
print("migrated", len(df), "rows")

3. Migrating Week 9's flat file into a `users` table

Week 7's parsing pattern, applied to a security-relevant file, landing in a real table.

Code
with sqlite3.connect("network.db") as conn:
    conn.execute("""CREATE TABLE IF NOT EXISTS users (
        id INTEGER PRIMARY KEY AUTOINCREMENT,
        username TEXT NOT NULL UNIQUE,
        password_hash TEXT NOT NULL
    )""")
    with open("users.txt") as f:
        for line in f:
            username, password_hash = line.strip().split(",", 1)
            conn.execute(
                "INSERT OR IGNORE INTO users (username, password_hash) VALUES (?, ?)",
                (username, password_hash),
            )

4. Login still works exactly the same way

checkpw() does not care whether the hash came from a file or a database row — Week 9's logic did not need to change at all, only where it reads from.

Code
import bcrypt

with sqlite3.connect("network.db") as conn:
    stored = conn.execute(
        "SELECT password_hash FROM users WHERE username = ?", ("alice",)
    ).fetchone()

if stored:
    print(bcrypt.checkpw(b"correct-horse-battery-staple", stored[0].encode("utf-8")))
