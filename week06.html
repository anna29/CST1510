5. When a column is numbers stored as text

A file can load a number-looking column as text — check .dtypes if arithmetic misbehaves. An object dtype where you expected numbers is the giveaway.

Code
readings = pd.DataFrame({"count": ["12", "45", "8"], "limit": [50, 50, 50]})
print(readings.dtypes)          # count is object (text), limit is int64

readings["count"] = readings["count"].astype(float)
# same result: readings["count"] = pd.to_numeric(readings["count"])

print(readings.dtypes)          # count is now float64
readings["percent"] = (readings["count"] / readings["limit"]) * 100
print(readings)

1. `iloc` - by position, `loc` - by label

With the default index they look the same, but they are asking different questions.

Code
import pandas as pd

servers = pd.read_csv("servers.csv")

print(servers.iloc[0])         # the row in position 0
print(servers.loc[0])           # the row labelled 0
print(servers.loc[0, "hostname"])

3. Boolean filtering

A comparison on a column gives back a Series of True/False. Putting that in [] keeps only the True rows.

Code

4. Combining conditions - `&` and `|`, not `and`/`or`

Each comparison needs its own brackets. and/or do not work row-by-row on a Series.

Code
east_over = servers[(servers["region"] == "east") & (servers["percent"] >= 90)]
print(east_over)

# servers[servers["region"] == "east" and servers["percent"] >= 90]
# ValueError: The truth value of a Series is ambiguous. Use &.

Common mistakes

Mistake What you see Fix
and/or between two column comparisons ValueError: The truth value of a Series is ambiguous use & / \| (bitwise), with brackets around each side
forgetting brackets around each comparison when combining TypeError or a wrong result (a) & (b), not a & b without brackets
df.loc[0] after filtering, expecting the first remaining row KeyError if row 0 was filtered out filtered rows keep their original label — use .iloc[0] for position
servers["region" == "east"] KeyError the comparison goes outside the column brackets: servers[servers["region"] == "east"]

Topic 4

Apply, Lambda and Finishing Up

Box we are building: STORE + PROCESS, the whole job

A lambda is a def you don't bother naming, for a one-line function you are only going to use once — usually right inside .apply().

Already know this? Skip to the Topic 4 Challenge.

1. `.apply()` runs a function on every value in a column

Start with a normal function, the way Week 3 taught it.

Code
import pandas as pd

servers = pd.read_csv("servers.csv")
servers["percent"] = (servers["used"] / servers["total"]) * 100

def classify(percent):
    if percent >= 100:
        return "OVER LIMIT"
    elif percent >= 90:
        return "WARNING"
    else:
        return "OK"

servers["status"] = servers["percent"].apply(classify)
print(servers)
Your turn

Write your own single-argument function and .apply() it to the used column.

2. `lambda` - the same idea, written inline

lambda parameters: expression — that IS the whole function. Only one expression allowed — no if/elif/else statements, no loops.

Code
double = lambda x: x * 2
print(double(21))     # 42 - same as def double(x): return x * 2
Code
def classify(p):                    lambda p: (
    if p >= 100:                        "OVER LIMIT" if p >= 100
        return "OVER LIMIT"             else "WARNING" if p >= 90
    elif p >= 90:                       else "OK"
        return "WARNING"             )
    else:
        return "OK"

same logic, same result - a block of statements vs one expression
Your turn

Write classify as a lambda with a chained conditional, and check it gives the same result as the def version for every row.

3. `.apply()` with a lambda, and `sort_values(key=...)`

lambda earns its place exactly here — a function small enough to write inline, used exactly once, right where it is needed.

Code
servers["status"] = servers["percent"].apply(
    lambda p: "OVER LIMIT" if p >= 100 else "WARNING" if p >= 90 else "OK"
)
print(servers.sort_values("hostname", key=lambda col: col.str.lower()))
Your turn

Use .apply() with a lambda to add a column region_upper — the region column, in capitals.

Common mistakes

Mistake What you see Fix
a lambda with an if statement (not an expression) SyntaxError lambda only allows one expression — use chained if/else, or write a def
reusing the same lambda logic in three places works, but repeats the logic three times that is the sign you wanted a named function, not a lambda
forgetting .apply() and just writing column.classify() AttributeError .apply(function) runs your function on every value — the function itself is not a method on the column
calling .plot() in a plain script and seeing nothing no chart appears add plt.show() (script) — a notebook shows it automatically
