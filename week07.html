Topic 1

Case and Whitespace

Real text arrives messy. This is the first, cheapest cleaning pass.

Already know this? Skip to the Topic 1 Challenge, then help a neighbour.

1.The problem case creates

"SRV-01" == "srv-01" is False — same server, different text. Nothing about Python assumes text means the same thing regardless of case; you have to say so.

hostname_a = "SRV-01"
hostname_b = "srv-01"

print(hostname_a == hostname_b)
print(hostname_a.lower() == hostname_b.lower())
Practice

Given ids = ["R-001", "r-002", "R-003"], print all three in lowercase.

2..upper(), .lower(), .title()

Each returns a new string — strings are locked (Week 4). The original never changes.

name = "record check console"
print(name.title())

original = "SRV-01"
print(original.lower())
print(original)   # unchanged
Practice

Explain in one sentence why original is unchanged after calling .lower() on it.

3..strip() — the single most important cleaning step

Removes whitespace from both ends. Real text almost always has some you cannot see in print().

raw = "  srv-01  "
print(f"[{raw}]")
print(f"[{raw.strip()}]")
Practice

Given " R-004 ", print it with the whitespace removed.

4..lstrip(), .rstrip(), and chaining

One side only, or a specific character instead of whitespace. Methods chain — .strip().lower() runs left to right.

messy = "***srv-01***"
print(messy.strip("*"))

field = "  SRV-01  "
print(field.strip().lower())
Practice

Given "///R-004///", strip just the / characters. Then chain .strip() and .upper() on a value of your own.

Challenge

Given raw = " SRV-01 ", produce "srv-01" in one line, chaining exactly the methods you need and no others.

Same idea, three fields

Field Looks like
AI / Data Science answer.strip().lower() before comparing survey responses
Cyber Security ip.strip() before checking it against a blocklist
IT hostname.strip().lower() before looking it up in your records

Common mistakes

Mistake What you see Fix
comparing text without normalising case False when you expected True .lower() both sides before comparing
assuming .strip() removes spaces in the middle it does not — only the ends that needs .replace(" ", "") instead
forgetting a method returns a new string the original "did not change", confusion reassign: x = x.strip()
stripping the wrong characters nothing removed, or too much removed .strip() alone means whitespace; .strip("*") means exactly those characters

Topic 2

Searching and Replacing

Before you can decide something about a line of text, you need to know what it contains.

Already know this? Skip to the Topic 2 Challenge.

1.in — does this substring appear?

line = "2026-09-08 ERROR failed to connect to srv-01"

print("ERROR" in line)
print("error" in line)          # case matters, same as any comparison
print("error" in line.lower())   # normalise first
Practice

Given log = "2026-09-08 WARNING disk 90% full", check whether it contains "WARNING", case-insensitively.

2..find() — WHERE, not just whether

Returns the starting index, or -1 if not found. Not an error, not None — check for -1 specifically.

position = line.find("ERROR")
print(position)     # 11

missing = line.find("WARNING")
print(missing)        # -1 - not found
Practice

Use .find() to locate where "disk" starts in the log string from section 1.

3..replace() — swap every occurrence

Case-sensitive, like everything else this week.

hostname = "srv_01_east"
print(hostname.replace("_", "-"))
Practice

Replace every - with _ in "srv-01-east".

4..startswith(), .endswith(), .count()

Very common for filtering — log levels, file extensions, repeated warnings.

lines = ["ERROR: disk full", "INFO: backup complete", "ERROR: timeout"]

for l in lines:
    if l.startswith("ERROR"):
        print("Needs attention:", l)

print("retry retry retry failed".count("retry"))
Practice

Given a list of filenames, print only the ones ending in ".log".

Challenge

Given a list of raw log lines, print only the ones that contain "ERROR" (case-insensitively), with "ERROR" replaced by "[FLAGGED]".

Same idea, three fields

Field Looks like
AI / Data Science "missing" in row.lower() to flag a bad survey response
Cyber Security line.startswith("FAILED") to filter failed logins
IT filename.endswith(".log") to find the files worth checking

Common mistakes

Mistake What you see Fix
checking .find(x) == True never true — .find() returns a number, not a bool use in for yes/no, .find() for position
treating -1 as falsy without checking a real match at position 0 gets missed by a careless if line.find(x): compare explicitly: if line.find(x) != -1:
.replace() not matching due to case nothing replaced, no error .lower() first if case should not matter
forgetting .startswith() needs the exact prefix False when text just contains it, not starts with it use in instead if position does not matter

Topic 3

Splitting, Joining and Building Strings

You have used .split() since Week 4. Here is the rest of it — plus its reverse.

Already know this? Skip to the Topic 3 Challenge.

1..split() with no argument

Splits on whitespace, any amount of it — handles uneven spacing automatically.

messy = "srv-01    used=87   total=100"
print(messy.split())
Practice

Split "a b c" (uneven spacing) with no argument and see what you get.

2.maxsplit — stop after N splits

Everything after the Nth split stays together, unsplit. This is exactly what lets you pull a hostname off the front of a line without also splitting whatever comes after it.

record = "srv-01,used=87,total=100"

print(record.split(","))
print(record.split(",", 1))
"srv-01,used=87,total=100".split(",", 1)
              |
              v
   ["srv-01", "used=87,total=100"]
    one split, everything after stays together
Practice

Split "hostname:srv-01:east" so that only the first : is used.

3..join() — the reverse of split

parts = ["srv-01", "87", "100"]
print(",".join(parts))
print(" | ".join(parts))
Practice

Join ["R-001", "R-002", "R-003"] into one line separated by " | ".

4..join() needs strings, and f-strings build clean output

.join() fails on a list of numbers — convert first. f-strings remain how you build a report line, same as Week 1, now with real cleaned data.

numbers = [87, 100]
# ",".join(numbers)  # TypeError: expected str instance, int found
print(",".join(str(n) for n in numbers))

hostname, used, total = "srv-01", 87.0, 100.0
print(f"{hostname:<10} {used:>6.1f}/{total:<6.1f}")
Practice

Given percentages = [87.0, 120.0, 45.0], build one comma-separated string of them formatted to 1 decimal place each.

Challenge

Same idea, three fields

Field Looks like
AI / Data Science splitting a CSV-style survey row before building a summary line
Cyber Security splitting "ip:port" before checking each part separately
IT splitting "key=value" pairs out of a status line

Common mistakes

Mistake What you see Fix
piece.split("=") when a value itself contains "=" ValueError: too many values to unpack use maxsplit: piece.split("=", 1)
.join() on a list of numbers TypeError: expected str instance, int found convert first: str(n) for n in numbers
assuming .split() and .split(" ") are identical different on multiple/irregular spaces no argument = whitespace, any amount; " " = exactly one space each time
forgetting .join() is called ON the separator AttributeError or wrong result ",".join(parts), not parts.join(",")

Topic 4

Parsing Real Text

Everything this week combines into one pipeline: strip, split, clean each piece, build a dict. This is exactly what this week's DEMO does.

Already know this? Skip to the Topic 4 Challenge.

1.The pipeline, one step at a time

raw_line = "  Srv-01 , used=87 , total=100  "

line = raw_line.strip()
hostname_part, rest = line.split(",", 1)
hostname = hostname_part.strip().lower()
print(hostname, "|", rest)
"  Srv-01 , used=87 , total=100  "
        | .strip()
"Srv-01 , used=87 , total=100"
        | .split(",", 1)
["Srv-01 ", "used=87 , total=100"]
        | .strip().lower() on the first piece, .split(",") on the rest
{"hostname": "srv-01", "used": 87.0, "total": 100.0}
Practice

Trace the same steps by hand on "srv-03,used=45,total=100" before running anything.

2.The whole pipeline as one function

def parse_line(raw_line):
    """Turn one messy raw status line into a clean dict."""
    line = raw_line.strip()
    hostname_part, rest = line.split(",", 1)
    hostname = hostname_part.strip().lower()

    fields = {}
    for piece in rest.split(","):
        key, value = piece.split("=")
        fields[key.strip().lower()] = float(value.strip())

    return {"hostname": hostname, "used": fields["used"], "total": fields["total"]}

print(parse_line("  Srv-01 , used=87 , total=100  "))
Practice

Adapt parse_line for a line shaped "hostname:region:used:total" instead (colon-separated, no key=value pairs).

3.When parsing breaks

Three different failures, three different meanings — knowing which is which is most of the job:

  • an extra = in a value → ValueError: too many values to unpack
  • a missing field → KeyError
  • a value that is not really a number → ValueError: could not convert string to float
# parse_line("srv-01,note=server=east,used=87,total=100")
# ValueError: too many values to unpack (expected 2, got 3)

# parse_line("srv-01,used=87")
# KeyError: 'total'

# parse_line("srv-01,used=unknown,total=100")
# ValueError: could not convert string to float: 'unknown'
Practice

Uncomment each broken call one at a time, run it, and check the error matches what is described above.

4.Parsing every line in a file

Real messy text does not arrive as one line typed into the code — it arrives as a file of many lines. Combine parse_line with Week 4's for line in f:, and write the status check once, as its own function, rather than repeating the if/elif inside the loop.

def status_of(used, total, warning_at=90):
    """Return OVER LIMIT, WARNING or OK for a used/total pair."""
    percent = (used / total) * 100
    if percent >= 100:
        return "OVER LIMIT"
    elif percent >= warning_at:
        return "WARNING"
    else:
        return "OK"

with open("messy_lines.txt") as f:
    for raw_line in f:
        record = parse_line(raw_line)
        print(record["hostname"], status_of(record["used"], record["total"]))
Practice

Save a few messy hostname , used=.. , total=.. lines of your own to a file. Read it line by line, parse each one with parse_line, and print its status — without writing the cleaning logic or the status logic more than once.

Common mistakes

Mistake What you see Fix
assuming every real line is well-formed the pipeline works until one day it doesn't know which error means what, before it happens live
cleaning after converting instead of before AttributeError — numbers have no .strip() always clean the text, then convert
writing the pipeline as one long line hard to debug when it breaks keep it as named steps, like section 1, until you are confident
repeating the OVER LIMIT / WARNING / OK check inline for every line the same logic typed twice, easy to make it disagree with itself write it once as status_of(...) and call it
