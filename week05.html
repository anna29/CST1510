Topic 1

Classes and Objects

A class is a blueprint. An object is one particular thing built from it.

Already know this? Skip to the Topic 1 Challenge, then help a neighbour.

1.A class defines the shape, __init__ fills it in

class Record:
    def __init__(self, label, value, limit):
        self.label = label
        self.value = value
        self.limit = limit

r1 = Record("R-001", 87.0, 100.0)

print(r1.value)

4.self — what it actually is

self is just this particular object. Python passes it in for you — you never write it in the call. Record("R-001", 87.0, 100.0) is really doing something closer to Record.__init__(new_object, "R-001", 87.0, 100.0).

class Broken:
    def __init__(value):    # missing self
        pass

# Broken(100)
# TypeError: __init__() takes 1 positional argument but 2 were given

Topic 2

Methods

A dict can only hold data. An object can hold data and the actions that belong to it.

Already know this? Skip to the Topic 2 Challenge.

1.A method is a function that lives inside a class

self gives it access to that object's own attributes — no need to pass them in again.

class Record:
    def __init__(self, label, value, limit):
        self.label = label
        self.value = value
        self.limit = limit

    def summary(self):
        """Return a one-line description of this record."""
        return f"{self.label}: {self.value}/{self.limit}"

r = Record("R-001", 87.0, 100.0)
print(r.summary())

2.self is whichever object made the call

Same method, same code — self becomes a different object depending on who called it.

r_a = Record("R-001", 87.0, 100.0)
r_b = Record("R-002", 120.0, 100.0)

print(r_a.summary())    # self was r_a here
print(r_b.summary())     # self was r_b here, same method
r_a.summary()                     r_b.summary()
     │                                  │
     ▼                                  ▼
def summary(self):                 def summary(self):
    return f"{self.label}..."          return f"{self.label}..."
     │                                  │
  self = r_a                         self = r_b
     │                                  │
     ▼                                  ▼
 "R-001: 87.0/100.0"               "R-002: 120.0/100.0"

3.One method can call another, through self

class Record2:
    def __init__(self, label, value, limit):
        self.label = label
        self.value = value
        self.limit = limit

    def percent(self):
        """Return value as a percentage of limit."""
        return (self.value / self.limit) * 100

    def status(self):
        """Return OVER LIMIT, WARNING or OK based on percent()."""
        p = self.percent()
        if p >= 100:
            return "OVER LIMIT"
        elif p >= 90:
            return "WARNING"
        else:
            return "OK"

r2 = Record2("R-002", 95.0, 100.0)
print(r2.status())

4.A method CAN change its own object's state

Week 3 taught you a function cannot reach outside itself and change your variable. A method is the exception — because self is the object, not a copy of it. This is a genuine difference, not a contradiction: the wall from Week 3 is still there, a method just has a key to its own room.

class Checker:
    def __init__(self):
        self.over_limit_count = 0

    def check(self, value, limit):
        """Update the running count if value is over limit."""
        if value > limit:
            self.over_limit_count += 1

c = Checker()
c.check(120, 100)
c.check(87, 100)
print(c.over_limit_count)   # 1 - it actually changed, no return needed
Practice

Topic 3

Many Objects Together

Week 4: a list of dicts. This week: a list of objects — same shape, and now each item can also do something.

Already know this? Skip to the Topic 3 Challenge.

1.A list of objects

class Record:
    def __init__(self, label, value, limit):
        self.label = label
        self.value = value
        self.limit = limit

    def status(self):
        percent = (self.value / self.limit) * 100
        return "OVER LIMIT" if percent >= 100 else "OK"

records = [
    Record("R-001", 87.0, 100.0),
    Record("R-002", 120.0, 100.0),
]

print(type(records))       # list
print(type(records[0]))     # Record - each ITEM is an object

Stretch: keeping the count on the class

A running total outside the loop (above) works fine and is enough. If you want the count to live with the Record class itself instead of a separate variable, a class attribute — assigned once, indented under the class but outside any method — is shared by every instance rather than copied per object:

class Record:
    over_limit_count = 0     # one shared counter, not one per instance

    def __init__(self, label, value, limit):
        self.label = label
        self.value = value
        self.limit = limit

    def status(self):
        percent = (self.value / self.limit) * 100
        result = "OVER LIMIT" if percent >= 100 else "OK"
        if result == "OVER LIMIT":
            Record.over_limit_count += 1
        return result

Every Record shares the same over_limit_count — read and update it as Record.over_limit_count, not self.over_limit_count (assigning through self. would silently create a separate, per-instance attribute instead of changing the shared one).

3.Loading objects from a file

Week 4's load_records built a list of dicts. The only real change: build a Record inside the loop instead of a dict.

def load_records(path):
    """Read label,value,limit lines from a file and return a list of Records."""
    records = []
    with open(path) as f:
        for line in f:
            label, value, limit = line.strip().split(",")
            records.append(Record(label, float(value), float(limit)))
    return records

This is what component meant in this week's system diagram box: the record and the logic that checks it are no longer separate — they are one reusable thing. Next week's pandas DataFrame works the same way underneath: rows of data, with methods that already know how to work on them.
