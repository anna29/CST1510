Part 1

Your First Program

Official docs: Built-in print()

By the end of this notebook you can make a program say something.

1.print()

print() puts something on the screen. Run the next cell.

print("Record check starting")

Text inside quotes is a string. Single or double quotes both work.

print('single quotes')
print("double quotes")

2.Printing several things

Commas put a single space between the values.

print("Record", "R-004", "checked")
print("Value", 23.7)

3.Blank lines and separators

print() on its own prints an empty line.

Multiplying a string repeats it — this is how you draw a line without typing it out.

print("=" * 34)
print("  RECORD CHECK")
print("=" * 34)
print("top")
print()
print("bottom")

4.Escape sequences

\n starts a new line. \t inserts a tab.

print("line one\nline two")
print("ID\tVALUE")
print("R-004\t23.7")

5.Comments

Anything after # is ignored by Python. Comments are for the human reading your code — including you, in three weeks.

# Show the report header
print("=" * 20)

Same idea, three fields

print() is how a program reports what it found.

Field Looks like
AI / Data Science Rows loaded: 1200
Cyber Security [ALERT] failed login from 10.0.0.5
IT Backup complete - 4 of 4 servers

Different job, same tool.

Mistake What you see Fix
print("hello) SyntaxError quotes must come in pairs
Print("hello") NameError lowercase print — Python is case sensitive
print "hello" SyntaxError the brackets are required
'it's fine' SyntaxError the apostrophe ends the string — use double quotes

Part 2

Variables and Types

Official docs: Built-in types · Built-in type()

By the end of this notebook you can store a value, use it again, and say what type it is.

1.A variable is a name for a value

Read = as "gets", not "equals". value = 23.7 means put 23.7 into value.

record_id = "R-004"
value = 23.7
limit = 20

print(record_id)
print(value)
print(limit)

Once stored, use the name wherever you would use the value.

print(record_id, "has value", value)

2.Types

Every value has a type. Ask Python with type().

print(type(record_id))
print(type(value))
print(type(limit))
Type Means
str text
int whole number
float number with a decimal point

The thing that catches everyone

These two print identically. They are not the same.

text_twenty = "20"
number_twenty = 20

print(text_twenty)
print(number_twenty)
print(type(text_twenty))
print(type(number_twenty))
print("20" + "20")
print(20 + 20)

3.Naming

Names should say what the value is.

Rules: lowercase, underscores between words, no spaces, cannot start with a digit, cannot be a Python word such as print, if or class.

# hard to read later
v = 23.7
l = 20

# easy to read later
sensor_value = 23.7
sensor_limit = 20

print(v - l)
print(sensor_value - sensor_limit)
x = "srv-01"
y = 87
z = 100
print(x, y, z)
# your rewrite here

4.Reassigning

A variable can be given a new value. The old one is gone.

checks_done = 0
print(checks_done)

checks_done = 1
print(checks_done)

checks_done = 2
print(checks_done)
a = 5
b = 10
a = b
b = 3
print(a, b)

Same idea, three fields

A variable holds one fact about one thing.

Field Looks like
AI / Data Science reading = 23.7, units = "celsius"
Cyber Security source_ip = "10.0.0.5", port = 443
IT hostname = "srv-01", disk_used = 87

Common mistakes

Mistake What you see Fix
23.7 = value SyntaxError the name goes on the left
my value = 3 SyntaxError no spaces — my_value
using a name you never set NameError assign it before you use it
"20" + 5 TypeError text and number — convert first (Topic 4)

When something behaves oddly, print the type. It is almost always this.

Part 3

Numbers and Arithmetic

Official docs: Numeric types · Floating point arithmetic

This is where a program stops storing and starts working things out.

Why do some decimal answers look too long?

In Python, many decimal values are stored as floating-point numbers. That is usually very useful, but it also means some values cannot be represented perfectly in binary.

For example:

print(0.1 + 0.2)
print(3.7)

You may sometimes see answers such as 0.30000000000000004 or 3.6999999999999993. That does not usually mean your formula is wrong. It means the computer is showing the closest stored floating-point value.

The important habit is:

  • use floats for measured values such as percentages, averages, or sensor readings
  • expect tiny representation differences in some decimal answers
  • format the result for people, for example with f"{value:.2f}"

1.The operators

Run this and compare all seven at once.

a = 17
b = 5

print("a + b  =", a + b)
print("a - b  =", a - b)
print("a * b  =", a * b)
print("a / b  =", a / b)
print("a // b =", a // b)
print("a % b  =", a % b)
print("a ** b =", a ** b)

2./ always gives a float

Even when it divides exactly.

print(10 / 2)
print(type(10 / 2))

// throws away the fraction. % gives what is left over.

print(10 // 3)
print(10 % 3)

Together they split a number into parts. This is more useful than it looks.

total_minutes = 137

hours = total_minutes // 60
minutes = total_minutes % 60

print(total_minutes, "minutes is", hours, "hours and", minutes, "minutes")

One split is useful. Chaining two splits, from the biggest unit down, is what you actually need for a stopwatch or a duration.

total_seconds = 4831

hours = total_seconds // 3600
remaining = total_seconds % 3600

minutes = remaining // 60
seconds = remaining % 60

print(total_seconds, "seconds =", hours, "hours,", minutes, "minutes,", seconds, "seconds")

Same idea twice: split off the biggest unit first with // 3600 and % 3600, then split what is left over into minutes and seconds the same way you already did above.

Your turn

9137 seconds is how many hours, minutes and seconds? Do it in two chained steps, the way the cell above does.

3.Order of operations

Python follows normal maths rules: ** first, then * / // %, then + -.

print(2 + 3 * 4)
print((2 + 3) * 4)

Habit worth forming: use brackets even when you do not need them. They cost nothing and remove all doubt.

print(10 + 6 / 2)

4.The calculation you will write most often

What share of the whole is this?

value = 23.7
limit = 20

difference = value - limit
percent = (value / limit) * 100

print("Difference:", difference)
print("Percent of limit:", percent)

5.Shorthand

Changing a variable using its own value is so common it has a short form.

count = 0

count = count + 1     # the long way
print(count)

count += 1            # exactly the same thing
print(count)

count += 5
print(count)

Same idea, three fields

Almost every calculation you write in year one is "what share of the whole is this?"

Field Question
AI / Data Science what percentage of rows are missing a value
Cyber Security what percentage of login attempts failed
IT what percentage of disk space is used

All three are (part / total) * 100.

Common mistakes

Mistake What happens Fix
2 + 3 * 4 when you meant (2 + 3) * 4 wrong answer, no error use brackets
dividing by zero ZeroDivisionError — program stops check the total is not 0
expecting 10 / 2 to be 5 it is 5.0 / always gives a float
3.6999999999999993 not a bug format it: f"{x:.2f}"

Part 4

Input, Casting and f-strings

Official docs: Built-in input() · Built-in int() · Formatted string literals

Boxes: INPUT and OUTPUT, properly

After this notebook you have everything you need for today's mini-project.

1.Asking for input

record_id = input("Record ID : ")
print("You entered:", record_id)

2.The one rule that catches everyone

input() always gives you text. Always. Even when the person types a number.

Run the next cell and type 23.7.

value = input("Value : ")

print("You typed:", value)
print("Its type is:", type(value))

So this would fail with a TypeError — Python received the characters 2, 3, ., 7, not a number.

Uncomment the line and see for yourself.

# print(value + 1)

3.Casting — converting a type

Function Turns something into
int() whole number
float() decimal number
str() text 
text = "20"
print(text, type(text))

as_number = int(text)
print(as_number, type(as_number))

Usually done in the same line as the input. Read it inside out: ask → get text → convert → store.

value = float(input("Value : "))

print(value + 1)
print(type(value))

Use float() unless you are certain the number is whole. int("23.7") fails with a ValueError.

4.f-strings

Put f before the quotes, then any variable in { }.

record_id = "R-004"
value = 23.7

print(f"Record {record_id} has value {value}")

You can calculate inside the braces too.

limit = 20
print(f"Over the limit by {value - limit}")

Forgetting the f is the most common slip. This prints the braces themselves:

print("Record {record_id}")

5.Formatting — making it look like a report

Written Shows Means
{value} 23.7 as is
{value:.2f} 23.70 2 decimal places
{value:>10} 23.7 right-aligned in 10 spaces
{value:>10.2f} 23.70 both
{diff:+.1f} +3.7 always show the sign 
percent = (value / limit) * 100

print(f"{percent}")
print(f"{percent:.2f}")
print(f"{percent:>12.2f}")

Right-alignment is what makes a report line up instead of looking like a mess. Compare these two.

difference = value - limit

print("--- without alignment ---")
print(f"Value : {value}")
print(f"Limit : {limit}")
print(f"Diff  : {difference}")

print()
print("--- with alignment ---")
print(f"Value : {value:>10.2f}")
print(f"Limit : {limit:>10.2f}")
print(f"Diff  : {difference:>+10.2f}")

Same idea, three fields

Ask for something, convert it, report it back cleanly.

Field Looks like
AI / Data Science f"Mean: {mean:.2f} over {n} rows"
Cyber Security f"[{level}] {failed} failed logins from {ip}"
IT f"{hostname:<12} disk {used:>3} %"

Common mistakes

Mistake What you see Fix
input("n: ") + 1 TypeError float(input("n: ")) + 1
int(input()) when they type 23.7 ValueError use float()
print("Value {v}") prints the braces you forgot the f
f"{value:.2}" odd result you meant .2f
